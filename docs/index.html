token-weather

A one-line forecast of your context window, drawn above the prompt. You see how full it is, how fast it is filling, and when compaction is coming, without opening /context.

Forecast bands

IconConditionContext used

↯Compact soon≥ 90%

What the band shows

  • Weather icon and word for how full the window is
  • Percentage used, and tokens used out of the window, like 134.4k / 200k
  • A sparkline of the last 12 turns
  • What the last turn added, like ▲ +98.3k last turn
  • Main-loop turns only; subagent turns are skipped. History lives in $.state, so it survives a hot reload.

blast-radius

Before a risky Bash command runs, it dry-runs what the command would touch and asks you to Proceed or Cancel. Cancel, or closing the dialog, denies the call and tells the model why.

What it stops to check

CommandDry run shown
rm -r, rm -rfSize (du -sh) and file count; flags / ~ . * as very wide
git reset --hardUncommitted files and diff stat
git clean -fgit clean -n: the files it would delete
git push --forceRemote commits that would be lost
git checkout -- ., git restoreWorking-tree diff stat
git branch -D, git stash drop|clearUnpushed commits, stash list
kubectl deletekubectl --dry-run=client: resources it would delete
SQL DROP / TRUNCATE, migrationsFlagged; no dry run possible

Know its limits

  • It reads the command text; it is a guard rail, not a sandbox.
  • Follows cd dir && … and git -C, so checks run where the command would.
  • Globs are not expanded and quoted paths with spaces are split, so the dry run can undercount.
  • With no one to ask (headless runs), risky commands are denied.
  • Each check has a 5-second limit; a failed check says so instead of hiding.

Method statement: build your own mod

Mods are plugins of function hooks: they observe, rewrite or answer what Claude Code does, and draw their own UI. The template gives you a slash command, a status line, a band and a tested state contract.

Four steps, in order

  1. Clone and scaffold

    Copies the template, renames it, lists it in the marketplace, then validates and tests it.

    git clone https://github.com/cskwork/claude-code-mods
cd claude-code-mods
scripts/new-mod.sh focus-timer "Pomodoro in the status line"

  2. Run it live

    Every save hot-reloads the mod in that session.

    claude --plugin-dir "$PWD/focus-timer"

  3. Write the hooks

    Every hook is ($, e, next): call next(e) to pass on, next({ ...e, x }) to rewrite, return without it to answer.

    focus-timer/
├── .claude-plugin/plugin.json
├── hooks/hooks.json
├── hooks/register.tsx
├── types/index.d.ts
└── tests/focus-timer.test.ts

  4. Check and ship

    Validate, test, push. Anyone can then install it from your marketplace.

    claude plugin validate focus-timer
claude plugin test focus-timer
git push

Site open. Sign in at the gate.

Three commands, then /reload-plugins. Both mods are small, read-only until you say otherwise, and live in one public repo.
